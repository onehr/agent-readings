Building Effective Agents

Anthropic argues that effective agentic systems usually start with simple LLM calls and only add workflows or autonomous agents when the task's uncertainty justifies the latency, cost, and control tradeoffs.

Why It Matters

The article gives a practical runtime taxonomy: augmented LLM, fixed workflow, and autonomous agent are different control surfaces with different debugging, cost, and trust requirements.

Problem

  • Teams often use the word agent for both fixed workflows and open-ended autonomous systems.
  • Frameworks can make agentic systems quick to start but can obscure prompts, responses, and tool behavior.
  • Complex multi-step systems can add latency, cost, and compounding errors when a simpler LLM call would suffice.

Key gap: The article addresses the missing practitioner taxonomy for deciding when to use a direct LLM call, a predefined workflow, or a model-directed agent.

Method

Use the simplest control pattern that satisfies the task. Start with a direct augmented LLM call, move to fixed workflows when decomposition is predictable, and reserve autonomous agents for open-ended tasks where the model must choose steps and tools over many turns.

  • Find the simplest solution, often a single LLM call with retrieval or examples.
  • If a task decomposes cleanly, implement a fixed workflow with checks or routing.
  • If subtasks cannot be predicted in advance, let an orchestrator or agent dynamically decompose the task.
  • For autonomous agents, keep environment feedback, sandbox testing, guardrails, and stopping conditions explicit.
  • Design and test tools as carefully as user-facing interfaces.

Agent Infrastructure Takeaways

  • Separate workflows from agents in the runtime API. Fixed code paths and model-directed control flow need different observability and safety expectations.
  • Treat complexity as a cost: every extra loop, branch, worker, or evaluator should have an evaluation reason to exist.
  • The augmented LLM is the reusable substrate; retrieval, memory, and tools should be documented as model-facing capabilities, not hidden implementation details.
  • Agent loops need environment observations, human checkpoints, sandbox tests, guardrails, and stopping conditions as first-class runtime concepts.
  • Agent-computer interfaces are infrastructure. Tool schemas, parameter names, path conventions, output formats, and examples can materially change reliability.

Caveats

  • This is a practitioner article based on Anthropic and customer experience, not a peer-reviewed research paper.
  • The framework and model examples can age as Anthropic products and agent frameworks change.
  • The article gives patterns and fit conditions, but not quantitative benchmark results for each pattern.
  • The advice is oriented toward LLM application builders and does not fully specify security boundaries for high-risk tool use.
  • Some tool-design examples are Anthropic-specific, though the interface lessons generalize.
