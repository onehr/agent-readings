ClawBench

Why It Matters

It treats browser-agent evaluation as an infrastructure problem spanning isolation, effect control, recording, reference collection, and outcome verification rather than as action prediction over static pages.

Problem

  • Static-trace web benchmarks evaluate action prediction over recorded pages rather than end-to-end task execution.
  • Self-hosted web environments improve reproducibility but omit production-site drift, authentication flows, anti-automation systems, and platform-specific validation.
  • Earlier live-web benchmarks primarily emphasize read-only information retrieval instead of purchases, reservations, applications, and detailed form submissions.
  • Executing write-heavy tasks on production services risks creating orders, messages, reservations, or other irreversible side effects.
  • URL, final-page, screenshot, or reference-action matching can miss alternative valid paths and does not expose enough evidence for auditing consequential workflows.

Key gap: The missing capability is a safe, auditable way to measure whether an agent can complete heterogeneous, state-changing daily web workflows on production websites.

Method

Collect broad everyday write-heavy tasks, have a human complete each task to identify the terminal committing request, run every model-task pair in a fresh instrumented browser container, block the matching terminal request at runtime, and score the retained agent trace against the human reference with a fixed Agent-as-Judge protocol.

  • Gather realistic write-heavy tasks from everyday website use and filter out read-only, unavailable, geographically restricted, paid, hard-verification, or unbounded-side-effect workflows.
  • Formalize each retained task as a task card with required personal data, expected final state, and a terminal submission target.
  • Record a human reference run and annotate the terminal request's URL pattern, method, and required payload fields.
  • Launch each model-task pair in a fresh isolated container with a clean Chromium profile, fixed resources, shared task data, and common browser actions.
  • Let the agent interact with the live production website while the extension and CDP sidecar record browser and network activity.
  • Capture and block the annotated terminal request before it reaches the server; leave ordinary page, image, analytics, and other non-terminal traffic intact.
  • Assemble the five-layer trace and compare it with the human reference and terminal payload through the fixed Agent-as-Judge prompt.
  • Aggregate binary verdicts into overall and category-level success rates, then use the recorded traces for failure diagnosis.

Agent Infrastructure Takeaways

  • A browser-agent benchmark measures a model-plus-harness system; the harness, prompt, browser configuration, and action interface must be held constant for comparative claims.
  • Effect control is strongest at a narrow, machine-checkable boundary: the terminal network request is easier to audit and block than an agent's stated intention.
  • The safety envelope is task-scoped. Workflows with multiple irreversible intermediate effects should be excluded rather than treated as covered.
  • Auditability requires synchronized evidence from the UI, network, agent transcript, low-level actions, and full-session replay.
  • Human references remain useful when they specify the target state and field bindings without forcing the agent to copy one exact action sequence.
  • Fresh browser profiles and isolated containers reduce cross-run leakage, but production-site and provider drift still need to be recorded and reported.
  • Binary success should be paired with trace-level diagnostics so last-mile hesitation, anti-bot blocking, early exit, and malformed submissions remain visible.

Caveats

  • Live production websites trade rerun determinism for ecological validity; layouts, A/B tests, region, account state, and anti-automation systems can change.
  • Final-request interception is not a general browser sandbox and only covers the audited terminal endpoint for each task.
  • Live sessions, model calls, network instrumentation, and trace-based judging make repeated trials and ablations more expensive than static benchmarks.
  • Reported model scores are conditioned on the shared OpenClaw harness and should not be read as model-only capability measurements.
  • Agent-as-Judge uses a binary pass/fail metric that compresses intermediate progress and retains non-zero disagreement with human reviewers.
  • Claude Sonnet 4.6 shares a model family with the judge, creating a potential evaluator-family effect despite the reported human audit.
  • The breadth-first suite underrepresents mobile-only, non-English, and accessibility-dependent workflows.
  • The paper's model results are a dated snapshot; later models, harnesses, site states, or benchmark versions can change the ranking.
