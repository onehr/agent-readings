CoALA

CoALA turns language agents into a cognitive-architecture design problem by separating memory modules, internal and external actions, and a looping decision procedure.

Why It Matters

For agent infrastructure, CoALA names the runtime pieces that need explicit interfaces: working state, long-term stores, tool/environment grounding, retrieval, reasoning, learning, and the top-level decision loop.

Problem

  • Early language agents often placed an LLM directly in a feedback loop with an external environment.
  • Newer agents added reasoning, planning, reflection, retrieval, and memory, but papers used inconsistent names for similar mechanisms.
  • Traditional cognitive architectures had mature notions of working memory, long-term memory, grounding, learning, and decision cycles, but required hand-specified symbolic rules.

Key gap: The paper addresses the lack of a systematic framework for comparing existing language agents and planning new ones at the architectural level.

Method

Map language agents onto a cognitive architecture: keep active state in working memory, persist experience and knowledge in long-term memories, expose grounding/retrieval/reasoning/learning as actions, and run a repeated decision cycle that plans before executing environment or memory-changing actions.

  • Frame LLM calls and prompt chains as production-like operations over text.
  • Import cognitive-architecture concepts to define memory modules and action types.
  • Classify recent agents by their long-term memory, external grounding, internal actions, and decision-making procedure.
  • Use the classification to identify reusable abstractions and underexplored design directions.

Agent Infrastructure Takeaways

  • Treat agent memory as typed runtime state, not only prompt text: working, episodic, semantic, and procedural stores have different persistence and mutation semantics.
  • Separate internal actions from external side effects. Retrieval, reasoning, and learning should be inspectable runtime operations before a grounding action touches the world.
  • The decision loop is the agent's main procedure, so production runtimes need explicit scheduling, observation capture, action parsing, and replay boundaries.
  • Procedural memory is broader than model weights: prompts, parsers, code skills, retrieval procedures, and learning policies can all become mutable agent state.
  • The framework is useful as a schema for reviews because it forces each paper to say which memory, action, and decision components it actually changes.

Caveats

  • CoALA is primarily a conceptual framework and survey, not a new empirical agent with benchmark results.
  • The framework does not by itself solve safety, permissions, persistence, or exactly-once execution for side-effecting agents.
  • The paper's categories are intentionally broad, so implementations still need concrete interface contracts and failure handling.
  • Autonomous updates to source code, retrieval, learning, or decision-making are flagged as risky and underexplored.
  • The paper assumes text is the dominant internal representation, while multimodal and embodied settings may require richer state.
