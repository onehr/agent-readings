FlashAttention

FlashAttention makes exact attention fast by tiling the computation so the quadratic attention matrix is never materialized in slow GPU HBM.

Why It Matters

For agents, every serving-layer gain compounds across long contexts and many calls; FlashAttention is the kernel-level reason longer prompts and cheaper serving became practical.

Problem

  • Self-attention has quadratic time and memory complexity in sequence length.
  • Approximate attention methods reduce theoretical compute but often fail to improve wall-clock time or reduce quality.
  • Standard attention materializes the N by N attention matrix and moves it through GPU HBM, making memory traffic a bottleneck.
  • Deep learning framework interfaces often hide fine-grained memory movement decisions needed for optimal kernels.

Key gap: The paper asks how to compute exact attention with fewer HBM reads/writes by explicitly designing for the GPU memory hierarchy.

Method

Load blocks of Q, K, and V into SRAM, compute attention tile by tile with online softmax, write only final outputs and small normalization state to HBM, and recompute tiles during backward rather than storing the whole attention matrix.

  • Partition Q, K, and V into blocks sized for GPU SRAM.
  • Loop over K/V blocks and Q blocks, loading only the active tiles into SRAM.
  • Compute local attention scores for the tile.
  • Update online softmax statistics and accumulated outputs without storing the full N by N score matrix.
  • Write final output blocks and small normalization values to HBM.
  • During backward pass, recompute required attention tiles on chip using saved normalization data.
  • Fuse attention operations into one CUDA kernel for fine-grained memory control.
  • Extend the same IO-aware pattern to block-sparse attention for longer contexts.

Agent Infrastructure Takeaways

  • Serving improvements start at the kernel. Agent workflows become cheaper when the primitive attention operation stops wasting HBM bandwidth.
  • FLOPs are not the whole cost model. For long-context agents, memory traffic and KV residency often dominate.
  • FlashAttention is exact, so it can improve throughput/latency without changing model semantics the way approximate attention might.
  • Longer context is an infrastructure feature. It changes what agents can carry in prompt state, tool traces, and retrieval context.
  • IO-awareness recurs up the stack: FlashAttention for attention matrices, PagedAttention for KV cache, SGLang for prefix reuse.
  • Better kernels do not remove the need for scheduling, paging, prompt compression, or durable state; they make those layers cheaper.

Caveats

  • The paper is primarily about training and attention kernels, though the kernel later became central to inference stacks.
  • Kernel speedups are hardware- and implementation-dependent.
  • Block-sparse FlashAttention is approximate and should not be conflated with exact FlashAttention.
  • Exact attention still has quadratic work in sequence length; FlashAttention reduces memory traffic and footprint, not the mathematical attention dependency.
  • The original 2022 results predate FlashAttention-2/3 and current production kernels.
  • Longer context can help agents but can also increase latency, prompt-management complexity, and exposure to irrelevant or malicious context.
